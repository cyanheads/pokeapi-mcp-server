# 0.2.0 — 2026-09-30

## Added

- **`evolutionDetails`** on each evolution step of `pokeapi_get_pokemon` and `pokeapi://pokemon/{identifier}` lists every upstream method with its requirements, version group, default flag, and forms. `trigger`, `minLevel`, `item`, and `condition` still summarize the first method ([#10](https://github.com/cyanheads/pokeapi-mcp-server/issues/10)).
- **`prices`** on `pokeapi_get_item` carries every version-group and currency row as `versionGroup`, `currency`, `purchasePrice`, and `sellPrice`. Null means not purchasable or not sellable in that row; zero is a literal amount ([#16](https://github.com/cyanheads/pokeapi-mcp-server/issues/16)).
- **`resolvedFromSpecies`** on `pokeapi_get_pokemon` and the Pokémon resource: a species name with no Pokémon record of its own (`deoxys`) returns its default variety (`deoxys-normal`) and names the species. Null when the identifier names a record directly ([#18](https://github.com/cyanheads/pokeapi-mcp-server/issues/18)).
- **`appliedFilters`** on `pokeapi_find_pokemon` echoes the normalized category filters, query tokens, and `limit`/`offset` on every successful response, in `structuredContent` and the text trailer ([#8](https://github.com/cyanheads/pokeapi-mcp-server/issues/8)).
- **`learnersIncluded`** on `pokeapi_get_move` separates a learner list that was not requested from one that was requested and is empty ([#13](https://github.com/cyanheads/pokeapi-mcp-server/issues/13)).

## Changed

- **`pokeapi_get_item` `cost`** (breaking) is `number | null`, was `number`: a value PokéAPI supplies is kept, zero included, and it is null when omitted. Items that reported `cost: 0` and "Not sold" now carry their prices in `prices`.
- **`pokeapi_find_pokemon` `query`** (breaking) longer than 100 characters is rejected at input validation. A call with no category filter returns no entries and a notice naming the required filters, with or without `query`.
- **Identifiers that cannot name a record** (breaking) fail as the declared `not_found`, or `invalid_filter` for `pokeapi_find_pokemon` category filters, on every lookup tool and both resources. Blank, `.`, `..`, and over-100-character identifiers are rejected without an upstream request; one that needs URL encoding is encoded once and never cached ([#17](https://github.com/cyanheads/pokeapi-mcp-server/issues/17)).
- **ID labels** (breaking for text parsers): `pokeapi_get_pokemon` headings read `PokéAPI ID: <id>` in place of `#<id>`, the `pokeapi_find_pokemon` table column is `PokéAPI ID`, and schemas describe Pokémon-record and species IDs rather than National Pokédex numbers. ID values are unchanged ([#12](https://github.com/cyanheads/pokeapi-mcp-server/issues/12)).
- **`pokeapi_get_item` text** renders `**Legacy cost:**` and a `## Prices` table in place of the `**Cost:**` line.
- **Docker image** installs production and OpenTelemetry dependencies in a build-platform stage through `scripts/install-otel.ts`, moves to `oven/bun:1.4.2`, and no longer sets `MCP_FORCE_CONSOLE_LOGGING`.
- **README and `.env.example`** document `LOG_TOOL_FAILURE_PAYLOADS`, `LOG_TOOL_FAILURE_PAYLOAD_MAX_BYTES`, and `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT`.
- **Development tooling** syncs the framework 0.13.10 scripts and skills: `lint:packaging` adds bundle-exclusion, manifest-version, and Dockerfile build-platform checks, and `lint:mcp` fails on a definition that cannot be imported.

## Fixed

- **`pokeapi_find_pokemon` past-end pages** keep `totalCount` and return a notice to retry with `offset: 0`, instead of reading as a search with no matches ([#11](https://github.com/cyanheads/pokeapi-mcp-server/issues/11)).
- **Text output states absent values** instead of dropping the line — `Not throwable`, `No known holders.`, `None`, `Not available` — and tags abilities regular or hidden and varieties default or alternative, so `content[]` carries what `structuredContent` does.
