# 0.3.2 — 2026-11-25

## Added

- **`pokeapi_get_item` and `pokeapi_get_move`** return `machines`, the TM, TR, or HM per version group (`move` on an item, `item` on a move), and `notices`; `version_group` limits the rows, an unknown group returns `invalid_version_group`, and a known group with no row returns no rows and a notice. Machine records are read under one 3-second budget per call and cached for the configured TTL; a row whose record could not be read, or was not read within the budget, reports null with a notice saying which. Once PokéAPI rate-limits a machine read, machine reads pause for every call for at least 5 s, or until its `Retry-After` passes when that is later (at most 60 s): skipped rows report null with a rate-limit notice, cached rows are still served, and main record reads are never affected. ([#36](https://github.com/cyanheads/pokeapi-mcp-server/issues/36))
- **`pokeapi_get_pokemon` and `pokeapi://pokemon/{identifier}`** return `pastTypes`, `pastAbilities`, and `pastStats`, each entry tagged with `throughGeneration`. ([#38](https://github.com/cyanheads/pokeapi-mcp-server/issues/38))
- **`pokeapi_get_type_matchups`** accepts `generation` (`generation-v`, `Generation V`, or `5`) and echoes it canonically: relations and Pokémon typings are as they stood then, without later types. An unknown value returns `invalid_generation`, and a type or Pokémon form introduced later returns `not_in_generation`. A 404 on the generation catalog, a later generation, or a Pokémon form record, or a Pokémon record that lists no form, reports an upstream failure (`ServiceUnavailable`), not a caller miss. ([#38](https://github.com/cyanheads/pokeapi-mcp-server/issues/38))
- **`pokeapi_get_type_matchups`** returns `offensiveByType`, each resolved type's attacking relations, and `type` accepts two types separated by `/`, `,`, `+`, or whitespace (`water/ground`). A repeated type collapses, three or more return `invalid_input`, and an unknown part is named in `not_found`. ([#37](https://github.com/cyanheads/pokeapi-mcp-server/issues/37))
- **`pokeapi_get_move`** returns `effectTextVersionGroup`. With no English effect description from PokéAPI, `effectText` is the latest English in-game text, shown beside that group in text output, and `shortEffectText` is null. ([#34](https://github.com/cyanheads/pokeapi-mcp-server/issues/34))

## Changed

- **`pokeapi_get_type_matchups`** no longer describes `type` as lowercase-only, and its description says PokéAPI records no relations for stellar, shadow, and unknown. **`pokeapi_team_builder`** step 3 points at `offensiveByType`. ([#37](https://github.com/cyanheads/pokeapi-mcp-server/issues/37))
- **`pokeapi_team_builder`** passes `generation` for older games and reads `pastTypes`, `pastAbilities`, and `pastStats`. ([#38](https://github.com/cyanheads/pokeapi-mcp-server/issues/38))
- **`pokeapi_find_pokemon`** describes `generation` with its accepted spellings.
- **`pokeapi_get_move`** describes `statChanges` as lacking user vs. target and condition.

## Fixed

- **`pokeapi_get_pokemon` `game_version`** matches in-game spellings such as `Omega Ruby`, `Let's Go, Pikachu!`, and `Legends: Z-A`; a miss notice reads `No English flavor text matches <input>. Showing the entry from <version>.` ([#33](https://github.com/cyanheads/pokeapi-mcp-server/issues/33))
- **`pokeapi_get_move`** `accuracy` and `power` report null where PokéAPI sends a placeholder 0, and their descriptions say so. ([#34](https://github.com/cyanheads/pokeapi-mcp-server/issues/34))
- **Evolution stage summaries** read the first `isDefault` alternative, else the first, and `condition` renders every populated requirement of it; the text step line no longer repeats the condition. ([#35](https://github.com/cyanheads/pokeapi-mcp-server/issues/35))
- **Evolution chains with an unspecified chance** (Milcery/Alcremie) no longer fail with an output-schema error: `conditionExpression.percentageChance` is nullable and renders `Chance: unspecified`.
- **`pokeapi_get_pokemon` `game_version`** treats a whitespace-only value as omitted.
- **`pokeapi_get_item`** falls back to the latest English flavor text for effect text as `pokeapi_get_move` does, skipping placeholder rows, and returns `effectTextVersionGroup`.
- **Flavor text** rejoins a word split by a soft hyphen before a line break.
- **A cache storage failure**, including a full in-memory store, is a miss and never a failed call.
- **`pokeapi_get_nature`** with identifier `list` no longer returns the cached nature catalog.
- **Evolution chains** are read from the configured `POKEAPI_BASE_URL`.
- **The exhausted-retry error's** `data.operation` reads `PokéAPI request`.
- **`pokeapi_get_pokemon` and the Pokémon resource** report an upstream failure instead of "Pokémon not found" on a 404 for the default variety a species names (`deoxys` → `deoxys-normal`), or for the species, evolution chain, or an ability of a resolved Pokémon; a name whose record and species both 404 is still `not_found`.
- **`pokeapi_get_type_matchups`** reports an upstream failure instead of `not_found` on a 404 for a type a Pokémon names, or for the default variety a species names.
- **A PokéAPI response that is not JSON**, from a main record or a version-group record read for `version_group`, reports an upstream failure (`ServiceUnavailable`) instead of a validation error.
