# 0.1.9 — 2026-09-19

## Changed

- With MCP_SESSION_MODE unset, empty, or an unsubstituted placeholder, HTTP defaults to stateless; an explicit meaningful value still overrides it.
- **Tool arguments** accept unambiguous case-style aliases and ignore known client-added metadata keys through the framework's pre-validation handling ([cyanheads/mcp-ts-core#452](https://github.com/cyanheads/mcp-ts-core/issues/452), [cyanheads/mcp-ts-core#453](https://github.com/cyanheads/mcp-ts-core/issues/453)).
- **Tool errors** carry `InvalidParams`, `invalid_arguments`, and recovery hints for rejected arguments; error text includes reasons and retryability when provided ([cyanheads/mcp-ts-core#445](https://github.com/cyanheads/mcp-ts-core/issues/445), [cyanheads/mcp-ts-core#458](https://github.com/cyanheads/mcp-ts-core/issues/458)).
- **Server instructions and README** describe the existing tool and resource behavior, including name-token filtering, optional move lists, flavor-text fallback, and dual-type offense limits.
- **Development tooling** moves maintained skills to `framework-skills/`, syncs build and packaging checks, adds `audit:fix` and CodeQL, and refreshes contribution forms and plugin metadata.
- **Bun runtime floor** rises from `>=1.3.0` to `>=1.4.0` to match the framework; Node remains `>=24.0.0`.
