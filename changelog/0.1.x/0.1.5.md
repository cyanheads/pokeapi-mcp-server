# 0.1.5 — 2026-06-12

## Added

- **`createApp()` identity** — `name` and `title` set explicitly to `pokeapi-mcp-server`, so the served `server_name` and `initialize` title carry the machine name rather than the scoped npm package name.
- **`scripts/clean-mcpb.ts`** — post-pack bundle cleaner wired into `bundle`. Runs `mcpb clean` (dev-dependency prune) then strips dependency-shipped agent docs (`node_modules/**` `skills/`, `.claude/`, `.agents/`, `SKILL.md`) that root-anchored `.mcpbignore` patterns cannot reach.
- **`Dockerfile` healthcheck** — `HEALTHCHECK` polls `/healthz` via Bun's built-in `fetch` (no `curl`/`wget`). Adds `org.opencontainers.image.version` label fed by an `APP_VERSION` build arg.
- **`lint:packaging` checks 5–9** — bundle-content guards (dev dirs excluded at root, `.mcpbignore` patterns anchored so they don't strip `node_modules/**` runtime paths, post-build `.mcpb` carries zero agent-doc entries) and an identity check that `name`/`title`/`display_name` equal the unscoped package name.
- **`check-framework-antipatterns` rule 4** — flags `z.coerce.boolean()` on env flags (`Boolean("false")` is `true`, so the flag can't be disabled); comment lines are skipped so JSDoc naming the pattern doesn't self-trip.

## Changed

- **`pokeapi_find_pokemon`** — `invalid_filter` error contract code changed from `InvalidParams` to `ValidationError`.
- **`pokeapi_get_type_matchups`** — `invalid_input` error contract code changed from `InvalidParams` to `ValidationError`.
- **`bundle` script** — uses `bun run build` (was `npm run build`) and appends the `clean-mcpb.ts` step.
- **`.mcpbignore`** — root dev-dir and config patterns anchored with a leading `/` (`/skills/`, `/.claude/`, `/Dockerfile`, …) so they match only at bundle root.
- **Vendored skills** under `skills/`, `.claude/skills/`, `.agents/skills/` re-synced to the framework version; adds the `techniques` skill.
- **Dependencies** — `@cyanheads/mcp-ts-core` `^0.9.21 → ^0.10.6`, `@types/node` `25.9.2 → 25.9.3`, `typescript` `^6.0.3 → ^5.9.3` (held to the 5.9 line; allowlisted in `devcheck.config.json`).
