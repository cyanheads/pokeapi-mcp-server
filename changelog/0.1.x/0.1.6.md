# 0.1.6 — 2026-06-20

## Added

- **`scripts/check-dependency-specifiers.ts`** — new devcheck step (`Dependency Specifiers`, `--no-dep-specifiers`) that hard-fails on floating specifiers (`latest`, `*`, pre-release dist-tags) in `package.json`'s dependency sections and `bun.lock`'s `workspaces` map. Catches `bun update --latest` writing a literal `latest` dist-tag into the lock's workspace map, which clears every other gate then lets the next `bun install` re-resolve past the manifest range. Static and local — runs in default and `--fast` passes. ([cyanheads/mcp-ts-core#246](https://github.com/cyanheads/mcp-ts-core/issues/246))
- **Plugin-manifest packaging checks** — `lint:packaging` check 10 validates `.claude-plugin/plugin.json` and `.codex-plugin/plugin.json`: non-empty descriptions, display fields carrying the unscoped machine name, and the `npx -y` install arg carrying the full scoped package name. Enabled by the new `devcheck.config.json` `packaging.pluginManifests` flag; the Packaging gate now runs when a plugin manifest is present. ([cyanheads/mcp-ts-core#240](https://github.com/cyanheads/mcp-ts-core/issues/240))

## Changed

- **Vendored framework scripts re-synced** to mcp-ts-core ^0.10.9 — fresh-scaffold guards in `build-changelog.ts`, `check-framework-antipatterns.ts`, and `devcheck.ts` (skip git-dependent checks and empty-changelog builds outside a repo), the `check-skill-versions.ts` worktree-deletion guard, and `lint-packaging.ts` check 10. ([cyanheads/mcp-ts-core#242](https://github.com/cyanheads/mcp-ts-core/issues/242), [#243](https://github.com/cyanheads/mcp-ts-core/issues/243), [#237](https://github.com/cyanheads/mcp-ts-core/issues/237))
