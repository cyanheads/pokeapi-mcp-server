# 0.1.4 — 2026-06-06

## Fixed

- **`pokeapi_get_type_matchups`** — throws `invalid_input` when both `type` and `pokemon` are supplied, instead of silently ignoring one. Matches the existing guard for the neither-provided case. (#2)
- **`pokeapi_find_pokemon` `format()`** — empty-result notice now reads "*(No results matched the filters. Try relaxing one or more filter values.)*", matching the text set via `ctx.enrich()`. Clients that only read `content[]` now receive the actionable guidance. (#3)
- **`PokeApiService.getDossier`** — fetches `pokemon/{id}` first, then derives the species identifier from `pokemon.species.name`. For variant forms (e.g. `pikachu-rock-star`), `pokemon-species/{form}` returns 404; the base species name from the pokemon response resolves correctly. (#4)
